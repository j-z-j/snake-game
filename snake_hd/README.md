# SNAKE HD v2 — 贪吃蛇（控制台高清版）

原 `tcs` 工程的审查结论、问题清单和优化说明见 **[…/代码审查与优化报告.md](../代码审查与优化报告.md)**。
本目录是重新实现的版本，**不覆盖原 `snake.c / test.c`**，可以和原工程并存。

> 需要**真彩色 emoji**（🍎🧊🛑💈）请用图形窗口版 **`../snake_gui/`**（GDI+，1100×700）。
> 本目录是纯控制台版，受 `CHAR_INFO` 限制只能用 2 字符图标。

## 1. 编译与运行

### 方式 A：Code::Blocks
打开 `snake_hd.cbp`，选择 Debug 或 Release，按 F9 编译运行。
工程已经配置好 `-lwinmm`、`-std=c11`、`-finput-charset=UTF-8`。

### 方式 B：命令行
```bat
build.bat
snake_hd.exe
```

或手动：
```bat
gcc -std=c11 -O2 -Wall -Wextra -finput-charset=UTF-8 game.c render.c main.c -o snake_hd.exe -lwinmm
```

要求：Windows 7 及以上，控制台窗口能容纳 **100 × 29** 字符（兼容默认的 120×29 窗口）。
程序会自动尝试 Consolas 9×18 / 8×16 / 7×14 / 6×12 四种字号；
如果窗口仍小于 100×29，程序会显示提示并退出，不会再出现文字换行、画面滚动叠在一起的问题。

> 如果之前运行过旧版、当前窗口颜色发蓝/发洋红，请**关掉这个控制台窗口重新打开**再运行。
> 新版只使用终端默认 16 色 + 纯黑背景，避免不同终端颜色表不一致。

## 3. 相比旧版的改动

- **零逐帧分配**：蛇身是头尾双指针链表，移动时把尾巴节点复用为新头，只有吃到食物才 `malloc` 一个节点。
- **O(1) 碰撞**：`occ[22][28]` 占用表，墙 / 自身 / 障碍物统一判定；不再有 `goto again` 死循环。
- **稳定计时**：`QueryPerformanceCounter` + 固定步长累加器，暂停不会“偷时间”。
- **操作跟手**：每帧读取控制台输入，最多缓存 3 次转向；快速连按不会丢键。
- **公平生成**：食物避开蛇身与障碍物；障碍物换位前闪烁 1.4 秒，且不会刷在蛇头前方 5 格。
- **双缓冲渲染**：整帧写入 `CHAR_INFO` 缓冲区，一次 `WriteConsoleOutputW` 输出，无闪烁；每帧整屏清空，切换场景不残留菜单文字。
- **视觉重做**：纯黑单一背景、亮绿色高对比蛇身、灰色线框 HUD、像素字分数、苹果 / 蓝宝石 / 红宝石、吃食物粒子；不再使用自定义调色板，避免某些终端忽略 `ColorTable` 后颜色错乱。
- **音效**：`sounds/eat.wav` / `bonus.wav` / `dead.wav`，用 `PlaySound` 异步播放；找不到 wav 时退回 `Beep`。
- **数据可靠**：最高分存 `snake_hd_best.txt`（exe 同目录、ASCII 文件名、`_wfopen`），只在破纪录时写一次。
- **音乐健壮**：MCI alias + `resume`，按 exe 目录查找 mp3，找不到时显示 `NO MP3`，不崩溃。
- **自测**：`snake_hd.exe --selftest` 跑 40000 步随机 / 贪心 AI，检查链表、占用表、食物、障碍物的一致性。

## 5. 音乐、音效与最高分

- 背景音乐：把 `kldykxq.mp3` 放在 exe 同目录，或 exe 的上两级 / 上三级目录。
- 音效：`sounds/` 目录随包提供 `eat.wav`、`bonus.wav`、`dead.wav`；如果移动了 exe，程序会向上找 1–3 级 `sounds/`。
- 最高分：`snake_hd_best.txt` 自动生成在 exe 同目录；第一次运行会尝试读取旧的 `high_score.txt`。
- 如果目录只读，游戏照常运行，只是不保存最高分。

## 6. 说明

控制台本身没有 3D 能力，所以这里的“建模”是**基于字符格的高对比像素表现**：

- 纯黑单一背景，不再铺棋盘格或大面积色块；
- 蛇是亮绿色实心块，尾巴两节深绿，头部用黑眼睛标方向；
- 食物/障碍只用形状和少量高饱和色区分：
  - 苹果：`@^`（红色果身 + 绿色叶子）
  - 蓝宝石：`[]`（青色 + 蓝色，像冰块）
  - 红宝石：`<>`（红色）
  - 障碍物：`||`（红/白/蓝三色循环，像理发店转灯）
- UI 用灰色细线框，暂停/结算整屏覆盖，避免右侧 HUD 干扰。

### 为什么不用 🍎 / 🧊 / 🛑 / 💈 本身

Windows 控制台的 `CHAR_INFO` 每个字符格只能存一个 UTF-16 码元；这些 emoji 都在 BMP 之外，是**代理对（两个码元）**，而且不同终端对 emoji 的宽度/字体支持不一致。直接写进去会变成两个乱码格或把 2 字符宽的格子撑破。
所以这里用“同语义的 2 字符图标”实现；如果你一定要彩色 emoji，需要改成 GDI/SDL 或 ANSI 文本渲染，我可以另做图形版。

逻辑层（`game.c`）与渲染层（`render.c`）完全解耦，后续如果换成 GDI / SDL，
只需要替换 `render.c`，游戏规则不用动。
